Firebolt lets you call large language models (LLMs) directly from SQL using Amazon Bedrock and Databricks.

- Use [`AWS_BEDROCK_AI_QUERY`](/reference-sql/functions-reference/ai/aws-bedrock-ai-query) to invoke a Bedrock model by providing a Bedrock model ID, a JSON request body, and a Bedrock `LOCATION` containing your AWS credentials. Alternatively, use [`AI_QUERY`](/reference-sql/functions-reference/ai/ai-query) to send a simple text prompt to a Bedrock endpoint.
- Use [`DATABRICKS_AI_QUERY`](/reference-sql/functions-reference/ai/databricks-ai-query) to invoke a Databricks serving endpoint by providing the serving endpoint name, a JSON request body, and a Databricks `LOCATION` with OAuth credentials.

LLM invocations in Firebolt count towards your account’s daily token budget. For details on how to set your token budget and check your current usage, see the sections below: [Set your LLM token budget](#set-or-change-your-llm-token-budget) and [Check your LLM token quota usage](#check-your-llm-token-quota-and-daily-usage).

<Note>
LLM token budget accounting is not available in Firebolt Core.
</Note>

<Note>
Before calling AI functions, an administrator must explicitly allow the corresponding AI services for your account: enable [`ALLOW_AMAZON_BEDROCK`](/reference-sql/commands/data-definition/alter-account/#alter-account-set-allow-amazon-bedrock) for Bedrock, and [`ALLOW_DATABRICKS_AI`](/reference-sql/commands/data-definition/alter-account/#alter-account-set-allow-databricks-ai) for Databricks.
</Note>

## Create a Bedrock LOCATION

Create a `LOCATION` once and reuse it wherever you need to call Bedrock models.

### Authentication options and examples

- **Access key and secret**

```sql
CREATE LOCATION bedrock_keys WITH
  SOURCE = AMAZON_BEDROCK
  CREDENTIALS = (
    AWS_ACCESS_KEY_ID = '<aws_access_key_id>'
    AWS_SECRET_ACCESS_KEY = '<aws_secret_access_key>'
  );
```

- **Temporary credentials (access key, secret, session token)**

```sql
CREATE LOCATION bedrock_temp_creds WITH
  SOURCE = AMAZON_BEDROCK
  CREDENTIALS = (
    AWS_ACCESS_KEY_ID = '<temporary_access_key_id>'
    AWS_SECRET_ACCESS_KEY = '<temporary_secret_access_key>'
    AWS_SESSION_TOKEN = '<temporary_session_token>'
  );
```

- **IAM role ARN**

```sql
CREATE LOCATION bedrock_role WITH
  SOURCE = AMAZON_BEDROCK
  CREDENTIALS = (
    AWS_ROLE_ARN = 'arn:aws:iam::123456789012:role/BedrockAccess'
  );
```

- **IAM role ARN with external ID**

```sql
CREATE LOCATION bedrock_role_external_id WITH
  SOURCE = AMAZON_BEDROCK
  CREDENTIALS = (
    AWS_ROLE_ARN = 'arn:aws:iam::123456789012:role/BedrockAccess'
    AWS_ROLE_EXTERNAL_ID = '<external_id>'
  );
```

To create a `LOCATION` using an IAM role (with or without an external ID), see [Use AWS roles to access Bedrock](/guides/ai/use-aws-roles-to-access-bedrock).

For all options and parameters, see [CREATE LOCATION (Amazon Bedrock)](/reference-sql/commands/data-definition/create-location-bedrock).

## Create a Databricks LOCATION

Create a `LOCATION` once and reuse it wherever you need to call Databricks serving endpoints.

```sql
CREATE LOCATION databricks_serving WITH
  SOURCE = DATABRICKS
  WORKSPACE_INSTANCE = '000-0000000000000.cloud.databricks.com'
  CREDENTIALS = (
    OAUTH_CLIENT_ID = '<client_id>'
    OAUTH_CLIENT_SECRET = '<client_secret>'
    -- Optional:
    -- OAUTH_SCOPE = '<oauth_scope>'
    -- OAUTH_SERVER_URL = '<oauth_server_url>'
  );
```

For all options and parameters, see [CREATE LOCATION (Databricks)](/reference-sql/commands/data-definition/create-location-databricks).

## Quick examples

Use these examples to try AI in Firebolt. For the full function reference and more details, see [`AWS_BEDROCK_AI_QUERY`](/reference-sql/functions-reference/ai/aws-bedrock-ai-query), [`AI_QUERY`](/reference-sql/functions-reference/ai/ai-query), and [`DATABRICKS_AI_QUERY`](/reference-sql/functions-reference/ai/databricks-ai-query).

### Invoke a model

<Note>
In the examples below, <code>my_bedrock_location</code> refers to a <code>LOCATION</code> object that you create using one of the methods described above (access keys, temporary credentials, or IAM role).
</Note>

```sql
SELECT AWS_BEDROCK_AI_QUERY(
    'amazon.nova-micro-v1:0',
    $${"schemaVersion": "messages-v1", "messages": [{"role": "user","content": [{"text": "What is the company name that aws belongs to?"}]}],"system": [{"text": "Fulfill the user's request"}],"inferenceConfig": {}}$$,
    'my_bedrock_location') AS result;
```

```sql
select AI_QUERY(
    'us.meta.llama3-3-70b-instruct-v1:0',
    'What is AWS?',
    'my_bedrock_location') as result;
```

<Note>
In the Databricks examples below, <code>databricks_serving</code> refers to a Databricks <code>LOCATION</code> object that you create in the section above. Your account must have [`ALLOW_DATABRICKS_AI`](/reference-sql/commands/data-definition/alter-account/#alter-account-set-allow-databricks-ai) enabled.
</Note>

```sql
SELECT DATABRICKS_AI_QUERY(
  'databricks-gpt-oss-20b',
  $${"messages":[{"role":"user","content":"What is AWS?"}],"max_tokens":128}$$,
  'databricks_serving') AS result;
```

### Invoke the LLM on multiple rows

```sql
SELECT n AS number,
       JSON_POINTER_EXTRACT_TEXT(
         AWS_BEDROCK_AI_QUERY(
           'amazon.nova-micro-v1:0',
           $${"schemaVersion": "messages-v1", "messages": [{"role": "user","content": [{"text": "$$ || n::TEXT || $$"}]}],"system": [{"text": "Write in english the capitalized name of the number that the user writes. Respond with a single word."}],"inferenceConfig": {}}$$,
           'my_bedrock_location'
         ),
         '/output/message/content/0/text'
       ) AS processed
FROM generate_series(1,3) s(n);
```

```sql
select n as number, AI_QUERY(
    'us.meta.llama3-3-70b-instruct-v1:0',
    'Write in english the capitalized name of the number. Respond with a single word: ' || n::TEXT,
    'amit_bedrock_location') as processed
from generate_series(1,3) s(n);
```

```sql
SELECT n AS number,
       JSON_POINTER_EXTRACT_TEXT(
         DATABRICKS_AI_QUERY(
           'databricks-gpt-oss-20b',
           $${"messages":[{"role":"system","content":"Write in english the capitalized name of the number that the user writes. Respond with a single word."},{"role":"user","content":"$$ || n::TEXT || $$"}],"temperature":0.1}$$,
           'databricks_serving'
         ),
         '/choices/0/message/content/1/text'
       ) AS processed
FROM generate_series(1,3) s(n);
```

### Sentiment analysis

```sql
SELECT JSON_POINTER_EXTRACT_TEXT(
  AWS_BEDROCK_AI_QUERY(
    'amazon.nova-micro-v1:0',
    $${"schemaVersion": "messages-v1", "messages": [{"role": "user","content": [{"text": "I love Firebolt."}]}],"system": [{"text": "Identify the sentiment in the user's sentence as a single uppercase word: POSITIVE or NEGATIVE. Respond with a single word."}],"inferenceConfig": {}}$$,
    'my_bedrock_location'
  ),
  '/output/message/content/0/text'
);
```

```sql
SELECT JSON_POINTER_EXTRACT_TEXT(
  DATABRICKS_AI_QUERY(
    'databricks-gpt-oss-20b',
    $${"messages":[{"role":"system","content":"Identify the sentiment in the user's sentence as a single uppercase word: POSITIVE or NEGATIVE. Respond with a single word."},{"role":"user","content":"I love Firebolt."}],"temperature":0.0}$$,
    'databricks_serving'
  ),
  '/choices/0/message/content/1/text'
);
```

### Set or change your LLM token budget

Set your account's daily LLM token budget to control how many tokens AI functions such as [`AWS_BEDROCK_AI_QUERY`](/reference-sql/functions-reference/ai/aws-bedrock-ai-query), [`AI_QUERY`](/reference-sql/functions-reference/ai/ai-query), and [`DATABRICKS_AI_QUERY`](/reference-sql/functions-reference/ai/databricks-ai-query) can process each day. By default, new accounts have a zero token budget.

```sql
ALTER ACCOUNT "<account_name>" SET (LLM_TOKEN_BUDGET = 10000);
```

For full syntax and details, see [`ALTER ACCOUNT`](/reference-sql/commands/data-definition/alter-account).

<Note>
Setting a token budget is not sufficient by itself. You must also explicitly allow usage of the relevant AI services for your account: enable [`ALLOW_AMAZON_BEDROCK`](/reference-sql/commands/data-definition/alter-account/#alter-account-set-allow-amazon-bedrock) for Bedrock and [`ALLOW_DATABRICKS_AI`](/reference-sql/commands/data-definition/alter-account/#alter-account-set-allow-databricks-ai) for Databricks.
</Note>

### Check your LLM token quota and daily usage

```sql
SELECT * FROM account_db.information_schema.quotas WHERE name='LLM_TOKEN_BUDGET';
```

If you exceed the daily budget, invocations of AI functions will fail until the limit resets or you increase the budget.

<Warning>
Using LLM functions such as <code>AWS_BEDROCK_AI_QUERY</code> on large tables or with many rows can quickly exhaust your daily LLM token budget and may result in significant costs in your AWS account. Always review your expected token usage and budget before running large-scale AI queries.
</Warning>
